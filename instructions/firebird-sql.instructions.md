# Firebird SQL dialect

Apply these when writing or reviewing SQL for a Firebird database. Firebird is not MySQL, PostgreSQL
or SQL Server, and the differences below are the ones that most often produce SQL that fails to
parse.

## Limiting rows

Firebird has no `LIMIT` and no `TOP`. Use either:

```sql
SELECT FIRST 10 SKIP 20 * FROM CUSTOMERS ORDER BY ID;   -- Firebird's own syntax
SELECT * FROM CUSTOMERS ORDER BY ID OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY;   -- SQL standard, Firebird 3+
```

`FIRST`/`SKIP` go immediately after `SELECT`, before the column list.

## The dummy table

Firebird requires a `FROM` clause. Use `RDB$DATABASE`, which always has exactly one row:

```sql
SELECT CURRENT_TIMESTAMP FROM RDB$DATABASE;
```

## Identifiers and case

Unquoted identifiers are folded to **upper case**, so `Customers` and `CUSTOMERS` are the same
object. A double-quoted identifier is case-sensitive and must be quoted every time thereafter —
prefer unquoted names unless the object was created with quotes.

## Auto-incrementing keys

There is no `AUTO_INCREMENT` and no `SERIAL`. Either an identity column (Firebird 3+):

```sql
CREATE TABLE ORDERS (ID INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, TOTAL NUMERIC(10,2));
```

or a sequence (generator) plus a `BEFORE INSERT` trigger:

```sql
CREATE SEQUENCE SEQ_ORDERS;
```

`GENERATOR` and `SEQUENCE` are the same thing; `SEQUENCE` is the standard spelling.

## Strings, concatenation and comparison

Single quotes only — double quotes mean an identifier. Concatenate with `||`, never `+`:

```sql
SELECT FIRST_NAME || ' ' || LAST_NAME FROM EMPLOYEES;
```

## Procedural SQL

Ad-hoc procedural code goes in an `EXECUTE BLOCK`:

```sql
EXECUTE BLOCK RETURNS (N INTEGER) AS
BEGIN
  N = 1;
  SUSPEND;
END
```

In a script run through `isql`, change the statement terminator around any block that contains
semicolons, or the block will be cut off at its first inner `;`:

```sql
SET TERM ^ ;
CREATE PROCEDURE TOTALS RETURNS (N INTEGER) AS
BEGIN
  N = 1;
  SUSPEND;
END^
SET TERM ; ^
```

A stored procedure returns rows with `SUSPEND` inside a `FOR SELECT ... INTO ... DO` loop.

## System catalogue

Metadata lives in `RDB$` tables (`RDB$RELATIONS`, `RDB$RELATION_FIELDS`, `RDB$PROCEDURES`,
`RDB$INDICES`, …); live monitoring lives in `MON$` tables (`MON$ATTACHMENTS`, `MON$STATEMENTS`,
`MON$TRANSACTIONS`). There is no `information_schema`.

## Schemas (Firebird 6+)

Firebird 6 introduced SQL schemas. Objects resolve through a session search path defaulting to
`PUBLIC, SYSTEM`. When more than one schema is in play, **qualify names explicitly** —
`SALES.ORDERS` — rather than relying on the search path, which will silently resolve to a
different table of the same name in another schema. Earlier versions have no schemas at all, so do
not qualify names for them.

## Transactions and DDL

DDL is transactional. In `isql` scripts, `COMMIT;` after DDL before the objects are used by
subsequent statements.
